# Atlas 多服务器管理工具功能文档

> 文档状态：初稿  
> 适用对象：Atlas 本体、Atlas Plugin、服务器管理员、后续 Mod/接口开发者

## 1. 概述

Atlas 是一款多服务器管理工具，核心目标是为多服务器环境提供统一的进程管理、日志识别、接口封装、服务器开关控制、远程文件管理与权限控制能力。

Atlas 本体保持精简，但直接具备多服务器管理能力，包括：

- 将 Minecraft 服务端作为子进程启动
- 通过 TUI 单独控制每一个子进程，并可控制主进程的守护进程
- 直接控制多个服务器的开服、关服、重启等开关操作
- 通过 SFTP 远程管理 Atlas 所管理每个服务器中的文件
- 日志识别与解析，并通过事件系统对外提供日志获取接口
- 将日志信息转换为可供 Atlas Plugin 调用的接口
- 调用玩家当前所在服务器终端执行命令并采集返回信息
- 远程 TUI 连接
- Command Tree and Event System：事件系统提供日志获取接口，命令树为插件提供标准命令系统，并衔接服务器命令系统与游戏内内置命令系统
- 插件支持热重载，可在不关闭服务器的情况下更新或启用/禁用插件
- 支持多种插件格式：单文件插件、打包插件（`.atlas` / `.rs`）、文件夹插件
- 配套权限管理系统，确保并非所有人发送的信息都能被执行
- 备份等扩展管理功能

具体扩展业务功能可通过 Atlas Plugin 调用 Atlas 提供的接口实现。

## 3. 进程管理与 TUI 控制

### 3.1 子进程启动服务端

Atlas 将 Minecraft 服务端作为子进程启动，由 Atlas 统一托管多个服务端进程。

### 3.2 TUI 单独控制子进程

通过 TUI，Atlas 可单独控制每一个子进程，实现对不同服务器进程的独立操作与管理。

### 3.3 主进程守护进程控制

通过 TUI，Atlas 还可以控制主进程的守护进程，用于保障 Atlas 本体与受管子进程的运行状态。

## 4. 当前实现范围

### 4.1 多服务器开关控制

Atlas 本体可以直接控制多个服务器的开关，包括开服、关服、重启等操作。该能力属于 Atlas 本体的多服务器管理能力，不依赖 Atlas Plugin 实现。

### 4.2 SFTP 远程文件管理

Atlas 可以通过 SFTP 远程管理其所管理的每个服务器中的文件。该能力用于对多个服务器进行统一的远程文件管理，属于 Atlas 本体的多服务器管理能力。

### 4.3 日志解析

Atlas 当前重点实现日志解析功能：识别服务器日志内容，并将日志信息转换为可供 Atlas Plugin 调用的接口。

### 4.4 返回信息接口

当前 Atlas 可以通过调用玩家当前输入的服务器终端，通过命令执行并采集返回信息，用于制作返回信息接口。

### 4.5 Atlas 本体定位

Atlas 本体功能较为精简，但直接承担子进程托管、TUI 子进程与守护进程控制、多服务器开关控制、SFTP 远程文件管理、日志解析、事件系统、命令树、终端命令返回信息接口、插件热重载与多插件格式加载等核心能力。扩展业务功能可由 Atlas Plugin 调用 Atlas 接口实现。

## 5. 命令树与事件系统

### 5.1 事件系统

事件系统即日志功能获取接口：Atlas 识别并解析日志后，通过事件系统向插件提供日志获取接口，使插件能够订阅和消费日志事件。

### 5.2 命令树

命令树为插件提供一个标准命令系统，并衔接以下命令来源：

- 插件标准命令系统
- 服务器的命令系统
- 游戏内的内置命令系统

通过命令树，Atlas 可对来自插件、服务器控制台与游戏内的命令进行统一的注册、解析与路由。

## 6. 插件系统

### 6.1 插件热重载

插件支持热重载，可以在不关闭服务器的情况下更新或启用/禁用插件。

### 6.2 插件格式

Atlas 支持多样的插件格式：

- **单文件插件**：以单个文件形式分发与加载。
- **打包插件（`.atlas` / `.rs`）**：以 `.atlas` 或 `.rs` 打包格式分发与加载。
- **文件夹插件**：便于开发复杂的多文件项目。

## 7. 权限管理与安全

Atlas 需要配套权限管理系统，确保并非所有人发送的信息都可以被执行。权限控制应覆盖：

- 指令来源与执行者身份
- 目标服务器范围
- 操作类型与危险等级
- 服务器开服、关服、重启等开关操作的执行权限
- SFTP 文件管理权限，包括文件浏览、上传、下载、修改、删除等操作
- 命令树中插件命令、服务器命令与游戏内内置命令的执行权限
- 子进程与守护进程的 TUI 控制权限
- 指令执行前的权限校验
- 必要时的操作审计与结果返回

### 示例功能

- 玩家在创造服务器输入 `!!op` 后，可获得该服务器的 OP 权限。
- 类似功能还包括备份等服务器管理操作。
- Atlas 直接控制多个服务器开关时，也必须经过权限校验，避免未授权用户执行开服、关服、重启等操作。
- Atlas 通过 SFTP 管理服务器文件时，应按服务器与操作类型进行权限校验。
- 命令树执行插件命令、服务器命令或游戏内内置命令时，应按来源与执行者进行鉴权。

## 8. 接口机制

### 8.1 日志到接口

Atlas 识别并解析服务器日志后，通过事件系统将日志信息封装为可供 Atlas Plugin 调用的接口。

### 8.2 终端命令返回信息接口

当前可通过调用玩家当前输入的服务器终端执行命令，获取返回信息并制作返回信息接口。

### 8.3 命令树接口

命令树为插件提供标准命令系统，并衔接服务器命令系统与游戏内内置命令系统，统一处理命令注册、解析与执行。

### 8.4 未来 Mod 接口

未来可支持通过 Mod 在游戏中获得所需信息并传输到 Atlas；也可通过 Mod 接口进行返回信息等功能。

## 9. 配置与数据源切换（未来）

未来 Atlas 可通过 config 修改接口数据源模式，选择：

1. 使用 Mod 获取接口
2. 抓取终端日志获取接口

### 9.1 Mod 获取接口

Mod 获取接口需要配置 IP 等信息进行网络连接。

### 9.2 终端日志抓取

日志抓取可通过相对路径或绝对路径控制服务器控制台，从终端日志中获取接口所需信息。

## 10. 日志格式兼容性

### 10.1 Fabric / Forge / NeoForge

Fabric、Forge、NeoForge 的日志行遵循 Log4j2 的基本模式。

### 10.2 Paper / Folia / Bukkit

Paper、Folia 和 Bukkit（CraftBukkit/Spigot）在日志格式上高度同源，均继承了 CraftBukkit 的命令日志核心格式。

Atlas 的日志解析应针对上述日志模式进行兼容识别与解析。

## 11. 未来规划

- 支持通过 Mod 在游戏中获取所需信息并传输到 Atlas。
- 支持通过 Mod 接口返回信息。
- 通过 config 切换 Mod 接口与终端日志抓取两种数据源。
- 完善权限管理系统，覆盖服务器开关、SFTP 文件管理、命令树执行与扩展功能。
- 扩展备份等服务器管理功能。

## 13. 术语说明

- **Atlas 本体**：精简的多服务器管理核心，直接负责子进程托管、TUI 控制、多服务器开关控制、SFTP 远程文件管理、日志解析、事件系统、命令树、插件加载与接口输出。
- **Atlas Plugin**：调用 Atlas 接口实现具体扩展业务功能的插件。
- **子进程**：由 Atlas 启动并托管的 Minecraft 服务端进程。
- **守护进程**：用于保障 Atlas 本体与受管子进程运行状态的主进程守护机制。
- **事件系统**：即日志功能获取接口，向插件提供日志事件订阅与消费能力。
- **命令树**：为插件提供标准命令系统，并衔接服务器命令系统与游戏内内置命令系统的统一命令机制。
- **SFTP**：SSH 文件传输协议，用于远程管理服务器中的文件。
- **插件热重载**：在不关闭服务器的情况下更新或启用/禁用插件。
- **单文件插件 / 打包插件（`.atlas` / `.rs`）/ 文件夹插件**：Atlas 支持的多种插件分发与加载格式。
- **终端日志抓取**：通过相对路径或绝对路径读取服务器控制台日志并解析。
- **Mod 接口**：通过 Mod 在游戏内获取信息、传输至 Atlas 或返回信息。
- **远程 TUI**：远程终端用户界面连接能力。
